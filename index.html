Dining Philosophers Problem

Understanding Process Synchronization, Deadlock and Starvation

A classic synchronization problem that demonstrates the fundamental challenges of coordinating multiple concurrent processes competing for a limited set of shared resources.

Start Learning
Fundamentals

The Basic Concept

A simple thought experiment formulated by Edsger Dijkstra to illustrate process synchronization dilemmas.

Problem Scenario

Imagine five philosophers seated around a circular dining table. Their lives consist exclusively of alternating periods of thinking and eating:

  • 1 Five philosophers are sitting around a circular table.
  • 2 There are five chopsticks placed between adjacent philosophers.
  • 3 Each philosopher spends their time THINKING.
  • 4 When hungry, a philosopher needs TWO chopsticks (left and right) to EAT.
  • 5 After eating, the philosopher PUTS DOWN both chopsticks.
  • 6 Then the philosopher starts thinking again.

Why is this a Synchronization Problem?

In Operating Systems terms:

Philosophers = Processes / Threads executing tasks.
Chopsticks = Shared Resources requiring mutual exclusion.
Eating = Critical Section requiring concurrent resource locking.

Without proper synchronization, multiple processes may hold onto one resource while waiting indefinitely for another, creating a Deadlock or leading to Starvation.

Pseudocode

Classic Philosopher Algorithm

The standard algorithm executed by each philosopher process i (where 0 ≤ i ≤ 4).

philosopher_process(int i) 
while true do
{
    THINK;

    PICKUP(CHOPSTICK[i], CHOPSTICK[(i+1) mod 5]);

    EAT;

    PUTDOWN(CHOPSTICK[i], CHOPSTICK[(i+1) mod 5]);
}
THINK

→ Philosopher is in the non-critical thinking state and does not require any chopsticks.

PICKUP

→ Philosopher attempts to acquire both their left and right chopsticks before eating.

EAT

→ Philosopher enters critical section and eats only when both chopsticks are acquired.

PUTDOWN

→ Philosopher releases both chopsticks after eating, making them available for neighbors.

Mathematics

Understanding (i + 1) mod 5

Why modulo arithmetic is used to model the circular table wrap-around seamlessly.

Philosopher (i) Left Chopstick [i] Right Chopstick [(i+1) mod 5]
P0 (i = 0) C0 C1
P1 (i = 1) C1 C2
P2 (i = 2) C2 C3
P3 (i = 3) C3 C4
P4 (i = 4) C4 C0 (Wrap-around)

Mathematical Walkthrough

Example 1: When i = 0 (Philosopher P0)
(i + 1) mod 5
= (0 + 1) mod 5
= 1
∴ P0 → C0 (Left) and C1 (Right)
Example 2: When i = 4 (Philosopher P4)
(i + 1) mod 5
= (4 + 1) mod 5
= (5) mod 5
= 0
∴ P4 → C4 (Left) and C0 (Right)

Key Insight: The modulo operator ensures the 5th philosopher (P4) wraps around to share the first chopstick (C0) with P0, closing the circular table loop.

DEADLOCK OCCURRED!

Each philosopher has picked up one chopstick (their left) and is waiting indefinitely for the second chopstick (their right), which is held by their neighbor. Because no philosopher can proceed or release their held chopstick, all five processes are permanently blocked.

Deadlock Analysis

The Four Coffman Conditions for Deadlock

Deadlock can only occur if ALL four of the following conditions hold simultaneously:

01

Mutual Exclusion

At least one resource must be held in a non-shareable mode (only one process can use it at a time).

In Philosophers: Each chopstick can be held by only ONE philosopher at any given moment.
02

Hold and Wait

A process currently holding at least one resource is waiting to acquire additional resources held by other processes.

In Philosophers: Each philosopher holds their left chopstick while waiting for the right chopstick.
03

No Preemption

Resources cannot be forcibly confiscated from a process; they can only be released voluntarily by the holding process.

In Philosophers: A philosopher cannot snatch a chopstick out of a neighbor's hand.
04

Circular Wait

A closed chain of processes exists such that each process holds a resource that the next process in the chain requires.

In Philosophers: P0 waits for P1, P1 waits for P2, P2 for P3, P3 for P4, and P4 waits for P0!
Concurrency Hazards

Understanding Starvation (Livelock)

What happens when a process waits indefinitely while other processes continue to make progress?

What is Starvation?

Starvation is an indefinite delay where a philosopher may repeatedly remain hungry because other philosophers continuously acquire the required chopsticks first.

Example Scenario: Philosophers P0 and P2 eat alternately. P1 (sitting between them) can never acquire both C0 and C1 at the same time and starves indefinitely, even though the system as a whole is not deadlocked!

Unlike Deadlock (where all progress stops), in Starvation some processes progress smoothly while one or more unfortunate processes never get service.

Solutions

Classic Synchronization Solutions

Techniques to prevent Deadlock and Starvation in the Dining Philosophers Problem.

1

Limit Active Philosophers

Allow at most four philosophers to sit at the table simultaneously (using a counting semaphore initialized to 4). By Pigeonhole Principle, at least one philosopher will always get two chopsticks.

2

Semaphore-Based Mutex

Represent each chopstick as a binary semaphore. A philosopher picks up chopsticks only if both are available inside a mutually exclusive critical section.

3

Monitors

Use a high-level monitor construct with condition variables. A philosopher can only transition to EATING if both left and right neighbors are not currently eating.

4

Arbitrator / Waiter

Introduce a centralized "waiter". A philosopher must ask the waiter for permission before picking up chopsticks. The waiter grants permission to only one philosopher at a time.

5

Asymmetric Resource Ordering

Break the circular wait symmetry: An odd philosopher picks up the left chopstick first then right, while an even philosopher picks up the right chopstick first then left.

Semaphore-Based Control Concept

A semaphore is an integer variable accessed only through two standard atomic operations: wait() (or P) and signal() (or V).

wait(S) • Acquire

Requests access to the resource. If value ≤ 0, the process blocks/waits. Otherwise, decrements value: S = S - 1.

signal(S) • Release

Releases access to the resource. Increments the value: S = S + 1, waking up any waiting process.

Comparison

Deadlock vs Starvation

Summary comparison table designed for second-year Computer Engineering examinations.

Feature Deadlock Starvation (Livelock)
Meaning Every process in the set is waiting for an event that only another waiting process can cause. A process waits indefinitely while other processes continuously receive the requested resources.
Condition Requires all 4 Coffman conditions (Mutual Exclusion, Hold & Wait, No Preemption, Circular Wait). Unfair scheduling or greedy neighboring processes claiming shared resources repeatedly.
Example All 5 philosophers hold their left chopstick and wait forever for their right chopstick. Philosophers P0 and P2 eat repeatedly; P1 in between never finds both chopsticks free.
System Result Complete system halt; zero throughput and zero CPU progress. System continues executing other processes, but specific victim processes starve.
Possible Solution Break circular wait (e.g. Asymmetric order, limit to 4 philosophers, arbitrator). Aging, fair FIFO queues, monitors with fair ticket scheduling.
